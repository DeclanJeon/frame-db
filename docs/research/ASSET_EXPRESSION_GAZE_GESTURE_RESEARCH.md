# FRAME DB 표정·시선·손동작 이미지 에셋 조사

조사·접근 기준일: **2026-10-30**. 문서 작성만 수행했다. 이미지 생성·다운로드·DB 변경은 하지 않았다.

## 1. 결론과 정확한 권장 수량

**권장: 성인 정체성 4명 × 고유 이미지 147장 = 588장.** 아래 수량·촬영 수치·행동 조합은 연구 결과의 최적값이 아니라 FRAME DB용으로 범위를 제한한 **제작 설계 제안**이다. 기존 category의 `target: 1400`을 이미지 제작 의무나 검증된 필요량으로 해석하지 않는다.

| 세트 | 정체성 1명당 조건/슬롯 | 고유 파일 수 | 정체성 4명 |
| --- | --- | ---: | ---: |
| E 기준 표정 | 중립 1 + 단일 행동 12 × 약/중 2단계 | 25 | 100 |
| C 창작 표정 | 장면 지시 12 × 시작/도착 정지 상태 2 | 24 | 96 |
| G 통제 시선 | 머리 yaw 3 × 시선 목표 9 = 27슬롯. 정면·렌즈 슬롯은 E00 중립 파일 재사용 | 추가 26 | 추가 104 |
| H 손동작 | 행동 24 × 관찰 시점 3 | 72 | 288 |
| **합계** | 148슬롯, E00/G 중앙 공유 1슬롯 | **147** | **588** |

표정만 E+C = **49장/명**, 시선은 **27슬롯/명 중 신규 26장**, 표정·시선 합계 **75개 고유 파일/명**이다. 손동작은 **24개 행동, 72장/명**이다. 총 592개 슬롯 참조가 588개 파일을 가리킨다. 썸네일·크롭·컨택트시트·재촬영·검수 탈락본·프롬프트는 신규 이미지 수에 더하지 않는다. C의 시작 상태가 E와 비슷해도 별도 장면 테이크로 촬영하며, 공유는 명시한 E00 한 건만 한다.

FACS는 관찰 가능한 얼굴 움직임을 분해하는 근거이고[S01], 시선 목표와 머리 자세를 분리한 실험 설계는 Columbia 원연구 자료에 근거한다[S05]. 손은 M3D의 형태·방향·사용 손 분리와 NHS의 접촉 설명을 이용한다[S07, S10]. **이 조합이나 수량이 감정 인식 성능을 보장한다는 주장은 하지 않는다.**

## 2. 실제 로컬 API 인벤토리

읽기 전용 `GET http://127.0.0.1:5190/api/export/all`의 JSON을 메모리에서 분석했다. 응답 전체를 파일로 저장하지 않았다. 이 요청의 `exportedAt`은 **2026-10-30T08:06:02.986Z**였다. 다음은 당시 스냅샷이며 이후 다른 세션의 변경은 반영하지 않는다.

| category ID | 정확한 이름 | 설명 | target | entry | entry_variants | media_assets |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| `expression` | 표정·시선 | 감정, 강도와 얼굴의 미세 반응 | 1400 | 50 | 0 | 0 |
| `gesture` | 손동작·제스처 | 손의 방향, 제스처와 접촉 | 1400 | 37 | 0 | 0 |

연결 수는 `reference_entries.category_id`로 entry ID 집합을 만든 후 두 테이블의 `entry_id`를 대조했다. 0은 이 API의 해당 연결 행 수이지 디스크·외부 사이트에 이미지가 전혀 없다는 뜻은 아니다. 기존 `details` 안의 `web_research`는 과거 수집 기록이며 이번 원문 확인을 대신하지 않았다.

ID 접두사별로 expression은 FS 16 + CRAFT 25 + web 9 = 50, gesture는 FS 8 + CRAFT 18 + web 11 = 37이다. 접두사는 집계 기준이며 사실성·권리·미디어 확보의 등급이 아니다.

### 2.3 인벤토리에서 생기는 설계 문제

- `수줍음`, `집중`, `단호함`, `경멸` 등은 검색·장면 의도 라벨로 보존할 수 있지만 이미지에서 확인한 내면 상태로 기록하지 않는다. 작은 비대칭 미소를 자동으로 경멸에 연결하지 않는다.
- `내쉬는 숨`, `잠깐`, `느린 깜박임`, `뒤`, `시선 이동`은 시간 정보다. 한 장의 사진은 시작·도착 상태만 보이며 속도·순서를 입증하지 못한다. FS-0021, FS-0024, FS-0026 및 CRAFT 전환 항목에 특히 중요하다.
- 손 인사 FS-0080/CRAFT-gesture-8c93799bff88, 머그 FS-0077/컵 그립 CRAFT-gesture-e81aca01031f 등은 개념·접촉 변형으로 연결하고 같은 이미지를 두 번 확보했다고 세지 않는다.
- web의 상징·도상·은유·비지시 항목은 분류 차원이지 각각 고정된 단일 손 모양이 아니다[S08]. 이번 24개 손 행동에 11개 web 항목을 무조건 한 장씩 배정하지 않는다.
- RAVDESS의 neutral/calm은 서로 다른 연기 코드다[S04]. 두 코드가 항상 시각적으로 구별된다는 가정 없이 E00은 이완된 비교 기준 하나로 정의한다.

### 접근 경로와 권리

RAVDESS 일반 페이지는 브라우저 확인 화면이 반환되어 원배포 API의 설명·라이선스를 읽었다. Apple은 긴 내비게이션 때문에 본문 변환 출력이 잘려 실제 HTML의 Gesture 표를 직접 확인했다. S01의 본문 변환에서 빠진 소개·FAQ도 원 HTML에서 읽었다. Johns Hopkins 손 해부 페이지는 보안 차단되어 근거에서 제외하고, 읽을 수 있는 S13으로 대체했다. 하위 위임은 세션 깊이 제한으로 실행되지 않았고 조사는 직접 수행했다.

S01/S02는 교육 내용 요약만 사용한다. S04/S05의 제한된 데이터셋을 FRAME DB의 공개·상업 이미지 공급원으로 간주하지 않는다. M3D 사이트의 TED 사용 허락은 해당 프로젝트·교육 프로그램을 위한 것으로 FRAME DB 허락이 아니다[S08, S09]. 그 외 출처의 예제 사진·도표도 이번 조사에서 재배포 권리를 확보하지 않았다. 권장 세트는 별도 촬영/제작과 정체성 사용 허락을 전제로 한 신규 기획이다.

## 4. 분류·표현 원칙

1. `observable_action`과 `scene_intent`를 별도 필드로 둔다. 전자는 보이는 형태, 후자는 작가가 부여한 맥락이다. `감정 정답`, `진짜 미소`, `거짓말 탐지`, `인격/진단` 라벨로 바꾸지 않는다[S01, S03].
2. `expression` 아래 `기준 얼굴행동`, `창작 연기`, `시선 통제`를 제안한다. 별도 gaze category나 DB 스키마 변경은 요청하지 않는다.
3. 손은 `handshape`, `palm_orientation`, `hand_owner`, `contact`, `task`가 우선이다. `기다려`, `반가워`, `공손함`은 문화·관계·대사와 연결한 연출 의도로만 둔다[S07, S08].
4. `source_claim`, `creative_direction`, `observed`, `measured`를 분리한다. 현재 문서의 사진 각도·접촉 QA는 제안이며 `observed/measured` 실적은 0이다.
5. 연구 라벨과 표정·손의 전형을 사람 전체에 투사하지 않는다. 4명은 비교 가능한 소규모 제작 묶음이지 문화·성별·연령·장애 다양성을 대표하는 통계 표본이 아니다.

## 8. G: 머리와 분리한 통제 시선 27슬롯/명

S05의 머리 자세/시선 격자 분리를 축소 적용한다. 좌표는 **인물 중심**으로 정의한다. yaw 음수는 인물 왼쪽, 양수는 인물 오른쪽이며 pitch 목표 음수는 아래, 양수는 위다. 정면 사진에서 인물 오른쪽은 대체로 화면 왼쪽이므로 `screen_direction`도 별도 기록한다. 이 부호는 본 문서의 제작 규약이지 기존 데이터셋 부호를 전사한 것이 아니다.

- 머리: yaw **-15, 0, +15도**의 3조건. pitch/roll은 0도.
- 시선: 카메라가 있는 기준 방향을 (0,0)으로 하여 수평 **-10, 0, +10도** × 수직 **-10, 0, +10도**의 9목표.
- 9목표는 좌하/하/우하/좌/중앙/우/좌상/상/우상이다. 모든 머리 조건에서 **같은 카메라 기준 목표 격자**를 본다. 머리를 돌렸다고 목표 격자를 함께 돌리지 않는다.
- 결과적으로 머리 0/목표 0은 E00을 공유하고, 머리 ±15/목표 0은 머리가 돌아가도 렌즈를 보는 별도 이미지다. 두 눈은 하나의 실제 목표에 수렴하도록 하고 따로 움직이게 지시하지 않는다.
- 목표 평면은 눈에서 카메라 쪽으로 2.0m. 수평/수직 오프셋은 각각 `2.0m × tan(10도) ≈ 0.353m`다. 이는 각 축의 평면 배치 정의이며 대각선 목표의 전체 편위가 10도라는 뜻이 아니다.
- 표적 ID/실제 위치, 눈 위치, 카메라 광축을 기록한다. 중앙 표적은 렌즈 중심이다. 가려진 표적은 카메라를 옮기지 않고 재배치·정렬 확인한다. 목표 각도는 보정된 시선 실측값과 다르다.

가까운 제품 초점·먼 창밖 초점·좌우 극단 응시·눈감음은 이번 격자에 넣지 않는다. `창밖을 보며 생각하기`, `제품 디테일 살피기`의 원근·대상 정보는 이 격자만으로 충족했다고 할 수 없다.

**사용법:** 렌즈 응시는 소개/직접 전달, 옆 목표는 상대 위치를 지정하는 장면에 사용할 수 있다[S06]. 같은 머리에서 눈 목표만 바꾼 열, 같은 목표에서 머리만 바꾼 행을 비교한다. 아래 시선에 수줍음·복종, 옆 시선에 거짓말을 자동 연결하지 않는다. 정확한 도수는 제작 목표와 보정 여부를 표시하고, 사진 외관만으로 각도를 측정했다고 기록하지 않는다.

### 예시 A: E07 약 단계

> 승인된 ID-A 얼굴 기준과 회색 상의, E 고정 카메라/조명을 사용한다. 머리 0/0/0도, 렌즈 응시. 양 입꼬리만 약하게 위·바깥으로 이동하고 입술은 닫는다. 눈썹·윗눈꺼풀·턱은 E00 기준을 유지한다. 얼굴 골격·홍채·점·피부색·입술 두께를 바꾸지 않는다. 행복·진정성 라벨은 부여하지 않는다. 근거 S01/S02, 행동 강도는 자체 약 단계. 제작 전 QA 상태는 not_produced.

### 예시 B: G 머리 오른쪽, 눈은 렌즈

> 승인된 ID-A와 E00 외형·촬영 조건을 유지한다. 머리는 인물 오른쪽 yaw +15도, pitch/roll 0도. 두 눈의 목표는 카메라 격자 (0,0), 렌즈 중심 하나다. 머리 방향으로 눈 목표를 따라 돌리지 않는다. 눈썹·입·턱은 이완 기준. 목표 거리 2.0m, 각도는 제작 목표이며 시선 실측값은 미확인이다. 근거 S05, 이 3×9 격자는 자체 설계.

### 예시 C: H10 접촉 상세 A

> 승인된 ID-A의 오른손·왼손 특징과 손톱을 유지한다. 오른 엄지와 검지가 같은 무브랜드 펜에 접촉하고 중지 옆면이 받친다. 펜 끝은 종이 표면, 왼손은 종이 왼쪽을 고정한다. 검지/엄지/중지의 앞뒤 순서와 펜 축이 일치해야 한다. 손가락 융합·펜 관통·손 소유 변경·종이 위 부유를 허용하지 않는다. H 상세 A 시점과 고정 조명을 사용한다. S10의 한 가지 접촉 예시이며 다른 기능적 그립을 틀렸다고 판정하지 않는다[S11].

| 시간 한계 | C 두 장에서 속도·순서의 실제 발생을, H 세 시점에서 tap/hold/swipe/반복을 검증했다고 쓰면 불합격. 시간 검증은 별도 연속 자료 필요[S09, S12] |
| 사용·권리 | 신규 촬영/제작의 사용 범위와 인물/소품 참조 연결 확인. 외부 연구 예제의 접근 가능성을 파일 재배포 허락으로 대신하면 보류 |

한 명이 프롬프트·행동·접촉을 검토하고 다른 검토자가 원본 크기와 비교 배열에서 정체성/좌우/가림을 확인하는 방식을 제안한다. 수량은 요청 파일 수가 아니라 **합격 고유 파일 수**로 닫는다. 불합격 재촬영은 새 행동을 늘리지 않는다.

## 12. 이번 조사에서 확인한 것과 남은 제작 작업

확인 완료: 로컬 API의 정확한 87개 ID/title와 두 category 행, 연결 variant/media 0건, 읽을 수 있는 13개 1차 연구·교육 출처, 147장/명·588장 전체의 산식, 고정 촬영 조건, 제작 키·사용법·프롬프트 필드·QA 제안.

미수행: 이미지 생성/수집, DB 수정, 유료 FACS 매뉴얼 열람·인증 코딩, 배우 미디어 전수 관찰, 실제 각도/접촉력 측정, 초상·데이터셋 상업 재사용 허락 취득. 이는 이 문서의 조사 범위를 넘어서는 후속 제작 작업이며 현재 완료량으로 합산하지 않는다.

문서 검증은 API 스냅샷과 ID/title 대조, 표의 행 수와 수량 산식, 출처 키 연결의 정적 검사로 수행한다. 순수 연구 문서이므로 애플리케이션 빌드·테스트·DB 쓰기 검증은 실행하지 않는다. 작업 디렉터리는 Git 저장소로 인식되지 않아 `git status` 기반 변경 대조는 사용할 수 없었다. 이번 작업의 파일 쓰기는 본 문서 한 곳의 apply_patch로 제한했다.
