# 웹 근거 기반 DB 채움 설계와 실행 예약

## Goal

완료된 Drive 이전과 홈페이지 검증 이후, 29개 분류 전체에 웹 근거를 갖춘 정보를 채우는 1차 실행을 설계하고 실제 의존성 실행 큐에 등록한다. 작업 목록·저장된 DAG 파일만으로 예약 완료라고 하지 않는다. 실제 run ID, 29개 수집 노드와 검수 노드의 등록 상태가 확인돼야 예약 완료다.

사용자 지시: “이거 전부 끝나고 프로젝트에 있는 DB들을 웹에서 정보들을 찾아서 만들어 채워야 한다. 설계를 하고 종류별로 채우는 작업도 예약 걸어놓자.” 현재 지시는 이전 단계의 ‘빈 DB는 설계까지’ 제한 뒤에 추가된 후속 실행 지시다. 유료 생성·원격 배포·외부 게시·커밋은 포함하지 않는다.

## 1. 기준선과 1차 범위

기준 시드: 2,485개 항목, 29개 분류, 미디어 2,914개, 검증된 Drive 표현 파일 7,167개. 24개 분류는 미디어가 없다. 조명·카메라·카메라 이동의 68개 도식은 실제 촬영·영상 자료와 구분한다. 기존 자료는 삭제하거나 새 정보 확보량으로 다시 세지 않는다.

1차 목표는 분류별 최대 20개 구별되는 근거 기반 개념, 합계 최대 580개다. 같은 개념의 기존 항목은 보강하므로 신규 행 580개를 보장하거나 목표 40,607개 전체 달성을 주장하지 않는다. 근거 부족·중복으로 목표에 미달하면 실제 수량과 부족 사유를 기록한다. 색·각도·압축본을 다른 개념으로 곱하지 않는다.

## 2. 자료원 선택

분류별 구체적인 1차 자료원과 확인 상태는 `docs/WEB_DB_SOURCE_RESEARCH.md`의 29개 분류 표를 사용한다. 제조사·도구 제공자·원저자·공식 교육기관·명시적인 공개 자료를 우선한다. 각 실행은 실제 페이지를 다시 열어 해당 주장과 버전을 확인한다. 검색 결과 문구만으로 사실을 확정하지 않는다. 로그인·결제·접근 차단이 필요한 자료는 수집 완료로 표시하지 않는다.

데이터 식별자·제작자·발행자·자료 유형·권리·관련 자료를 분리하는 기록 설계는 DataCite의 필드 구분을 참고한다. 데이터와 활동, 책임 주체, 원출처·파생 관계를 구분하는 원칙은 W3C PROV-O를 참고한다. 전체 표준이나 RDF 구현을 도입하는 작업은 아니다.

## 3. 수집 파일 계약

각 분류는 `data/web-research/staging/{category_id}.json` 한 파일을 쓴다. 공통 파이프라인이 먼저 JSON 계약·검증 CLI·DB 반영 경로를 구현하고 테스트한다. 수집 노드는 앱이나 정규화 코드를 수정하지 않는다.

배치 필수 값: schema_version, category_id, collected_at, sources[], records[].

자료원 필수 값: source_id, 실제 원문 URL, 원문 제목, 발행 주체, 확인 시각, 접근 결과, 관련 절·근거 위치, 권리 상태와 증빙 URL. 공개 열람 가능과 이미지·영상·음성 재배포 허용을 동일시하지 않는다.

항목 필수 값: concept_key, 한국어 제목, 세부 분류, 짧은 요약, 분류별 사실 필드 최소 3개, 각 사실의 source_id와 근거 위치, source_claim/observation/measurement/proposal 구분, 태그, 같은 개념의 기존 entry_id가 있으면 명시. 제안은 사실과 분리한다. 모르는 소재·치수·효과·성격·권리 정보를 추정해 채우지 않는다.

미디어 후보는 별도 media_candidates[]에 원출처·매체·이용 조건·역할을 기록한다. 후보 링크만으로 media_assets를 만들거나 미디어 확보량을 올리지 않는다. 1차 웹 정보 배치는 새 미디어 생성·다운로드·Drive 업로드를 자동 실행하지 않는다. 실제 매체 확보는 권리와 Drive 미러 검증을 통과하는 별도 후속 단계다. 기존 홈페이지 이미지는 계속 Drive만 사용한다.

## 4. 중복·계보·권리

- 기본 키는 category_id와 정규화된 concept_key다. URL이나 언어 표기 차이만으로 새 개념을 만들지 않는다.
- 기존 ID·상태·저작 구분을 보존한다. 동일 개념이면 근거와 정보만 보강하고 기존 가이드를 외부 참조로 임의 승격하지 않는다.
- 여러 출처는 같은 항목에 연결하고 서로 다른 주장·관찰은 합쳐 확정하지 않는다. 상충 내용은 각각 출처와 함께 기록한다.
- 원문 전체·장문 프롬프트를 복제하지 않는다. 짧은 한국어 사실 정리와 링크를 사용한다. 인용과 한 페이지에 과도하게 의존한 재서술을 제한한다.
- 미디어 권리 상태는 unknown / restricted / explicit_open / owned로 구분하고 허용 범위·저작자·라이선스 URL·수정 이력을 보존한다. CC BY 4.0 자료도 표시·라이선스 링크·변경 고지 조건을 검토하며, 별도 인격·초상 등 권리를 자동 확보했다고 간주하지 않는다.
- 실제 값만 비용·확인일·미디어 수로 집계한다. 유료 API·구매·생성·계정 연결을 새로 실행하지 않는다.

## 5. 독립 검수와 반영

수집과 검수는 별도 노드다. 검수는 실제 원문을 다시 읽고 모든 채택 항목의 사실·근거·중복·권리 표기를 대조한다. 형식 검사나 HTTP 200만으로 사실 검증 완료라고 하지 않는다. 검수 파일에는 입력 SHA-256, 채택 concept_key, 거절 사유, 자료원 재확인 결과, 실제 수량과 부족분을 쓴다.

검수된 concept_key만 정규화 파이프라인으로 반영한다. 다수 수집 노드는 서로 다른 파일만 쓰고, 정규화 시드·DB를 쓰는 작업은 한 번에 한 노드만 실행한다. 기존 갤러리·Drive 매핑·이미지 해시는 변경하지 않는다. 재실행은 멱등이고 기존 컬렉션·사용자 데이터는 보존한다.

파이프라인은 검수 입력이 바뀌거나 근거 파일이 없으면 반영하지 않는다. 웹 항목과 출처를 기존 관계형 테이블에 연결하고, 새 시드가 실제 DB에 반영되도록 데이터셋 개정 식별자를 갱신한다. 정보 확보와 실제 이미지·영상·음성 확보는 따로 표시한다. 문서 출처 링크를 갤러리 이미지인 것처럼 안내하지 않는다.

## 6. 예약 토폴로지와 완료 조건

공통 적재 기반 → 헤어·메이크업 수집 → 각 분류 독립 검수 → 파일럿 DB 반영·실증 → 나머지 27개 수집/독립 검수 → 단일 최종 반영 → 실제 테스트·타입·빌드·API·화면 검증.

29개 분류 각각 수집과 검수 노드를 갖는다. 모든 노드의 파일 쓰기 범위를 분리하며, 최종 반영은 검수된 파일만 읽는다. 실제 실행 ID와 노드 상태는 예약 후 별도 실행 원장에 기록한다. 아직 등록되지 않은 실행 ID나 미래 완료 수량은 문서에 넣지 않는다.

분류별 목표가 미달하면 실제 채택 수량을 공개한다. ‘예약 완료’, ‘웹 정보 반영 완료’, ‘미디어 확보 완료’는 서로 다른 상태다. 수집 노드의 완료 메시지만으로 반영 완료를 주장하지 않는다. 실패는 해당 생산·검수 노드만 재시도하며 이미 검증된 분류를 다시 수집하지 않는다.
